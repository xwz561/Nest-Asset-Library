# 菜单与对话框状态动效设计

## 意图

借鉴 Headless UI 的状态驱动进出场方式，让小旺仔素材库中的菜单、子菜单、弹出面板和模态对话框开合更连贯。应用继续使用现有 React 组件、主题样式与 `motion-polish.css`。

## 目标

- 所有应用菜单与弹出面板都有进入和离开过渡，包括工具栏筛选/排序、资源库切换、右键菜单、悬浮子菜单和文件夹图标菜单。
- 所有应用模态对话框与偏好设置窗口都有进入和离开过渡；遮罩和对话框本体协调播放。
- 关闭时元素保持挂载到离场结束，再卸载；离场期间不可交互。
- 保留原有关闭途径、忙碌/禁用条件、Portal 定位、层级和主题外观。
- 尊重减少动态效果设置；该设置开启或不支持动画时直接切换。

## 非目标

- 不替换现有菜单语义、键盘逻辑或对话框组件。
- 不调整素材卡片、页面切换、开关、主题动画或桌面宠物动画。
- 不动画应用侧栏、顶栏、主内容布局，不改变字体、文字、尺寸或颜色。
- 不引入 Headless UI 依赖，也不重做原有视觉样式。

## 反目标

- 不通过高度、位置、边框宽度等布局属性制造开合动画或页面跳动。
- 不在素材卡片上增加常驻动画、`will-change`、`backdrop-filter` 或新的滚动期动画。
- 不改变 Escape、遮罩点击、忙碌状态或选项执行时的关闭行为。

## 方案比较

1. **直接加入 Headless UI Transition**：可复用 `Transition` / `TransitionChild` 的生命周期和父子协调能力；会增加依赖，并需要让现有 Portal、Fluent UI 控件、焦点与关闭逻辑适配新的包装层。
2. **自建共用状态过渡层（选定）**：用轻量 React presence 组件管理 `entering → entered → leaving → unmounted`，通过 `data-motion-phase` 交给 CSS 动画；沿用现有 React、主题和动效令牌。实现时需要逐类包住现有菜单与模态根节点，并处理离场期间的 `inert` / `aria-hidden`。
3. **只用 CSS `@starting-style`**：改动少，适合进入动画；现有组件由条件渲染直接卸载，无法可靠完成离场阶段，因此不能满足本需求。

选择方案 2：复用 Headless UI 的状态驱动思路，保持本项目的组件与动效系统。

## 动效规范

- 菜单/弹出层：进入 180–220ms，使用透明度、最多 4px 的独立位移和轻微缩放；离开约 160ms，透明度和缩放淡出。
- 对话框遮罩：约 160–200ms 淡入/淡出；对话框本体进入约 220ms，轻微上浮（最多 6px）并淡入，关闭 160ms 淡出并缩至约 0.98。
- 曲线只使用现有 `--apple-ease`、`--motion-ease`。动画只使用透明度、独立 `translate` / `scale`；终态回到原有样式。
- 遵循 `prefers-reduced-motion`，开合直接完成。
- 滚动中的菜单/弹出层不启动新动效；菜单所在工具栏在离场期间继续允许溢出，避免裁切。

## 覆盖范围

- `role="menu"` 菜单与已有的菜单/弹出层根节点，包括 Portal 菜单与悬浮子菜单。
- 使用遮罩的模态对话框，包括通用对话框、扩展/友商工具、更新/关于/支持、查找/转发/批量操作、团队协作、AI Flow 导入、偏好设置及教程/使用演示弹窗。
- 原生 `select` 下拉、非模态侧栏/助手面板、素材预览器和桌面浮动卡片不属于此范围。

## 交互与可访问性

- presence 组件保留原菜单或对话框根节点，Portal 的容器、定位和层级不变。
- 进入阶段可以交互；离场阶段设置 `inert` 与 `aria-hidden`，禁用指针事件；动画结束或安全计时后卸载。
- 若离场期间重新打开，同一节点切回进入阶段并取消卸载计时。
- 关闭仍由现有按钮、Escape、遮罩点击和业务回调触发；忙碌时原有禁止关闭规则保持不变。
- 背景遮罩先后与内容面板同步淡入/淡出，避免内容瞬间消失或遮罩残留。

## 性能与主题约束

- 动效规则放在 `src/motion-polish.css`，选择器限定在弹出层/对话框，不覆盖应用全局布局。
- 颜色、字体、边框和内容排版保持原样；所有主题复用同一动效，不新增视觉色值。
- 不在滚动期间启动新动画；不碰素材卡片的滚动优化规则。

## 实施与验收

- 将当前筛选/排序试做抽成共用 presence 组件，再接入上述菜单、Portal 子菜单和模态根节点。
- `npm run build` 成功；手动检查代表性的工具栏菜单、右键子菜单、偏好设置和忙碌中的对话框，确认开合、遮罩、层级、焦点和关闭行为保持正确。
- 验收所有主题下的视觉一致性，并确认减少动态效果设置跳过动画。
- 本轮只改源码与必要的动效样式；不更改版本、不打安装包、不提交或推送。

## 留给实现者

- 选择 presence 组件 API、定时器清理方式和各组件的最小接入点。
- 根据现有 CSS 结构挑选菜单与对话框的准确入场方向及缩放幅度，但遵守上述时长与属性边界。
